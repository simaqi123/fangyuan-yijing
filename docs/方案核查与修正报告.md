## 二、发现的 5 处硬错误（照抄文档会失败）

| # | 文档原文 | 实机真相 | 后果 |
|---|---|---|---|
| 1 | `systemctl --user stop vllm.service` | **本机无此服务**。vLLM 跑在 Docker 容器 `vllm-qwen38`（另有 `vllm-proxy` 同镜像） | 命令报错，停不掉，以为停了其实还在跑 |

## 三、1 个被漏掉的真正风险（最高优先级）

### 模型不是「普通稠密 Transformer」，是「混合线性注意力」架构

实测 `config.json`：

```
architectures : ["Qwen3_5ForConditionalGeneration"]
model_type    : qwen3_5
num_hidden_layers : 64
hidden_size       : 5120
num_attention_heads : 24
full_attention_interval : 4
layer_types   : [linear, linear, linear, full, linear, linear, linear, full, ...]
mtp_num_hidden_layers : 1          ← MTP 投机解码层
vision_config : { hidden_size: 1152, out_hidden_size: 5120 }   ← 视觉塔
```

**含义**：每 4 层里 3 层是线性注意力、1 层是全注意力。它不是标准全注意力 Transformer。

**风险**：transformers 5.x 认识它（已实测），但 **Unsloth / LLaMA-Factory 对 `linear_attention` 层的训练适配尚未验证**。如果框架不认识这个层类型，**停服一整个周末也训不起来**——这正是最需要提前排掉的不确定性。

## 五、下一步建议

**不建议现在停服。正确顺序是：先过 G0.5，再决定停不停服。**

G0.5 三道判定（全程不停服、不加载 54GB 权重）：

| 判定 | 内容 | 通过标准 |
|---|---|---|
| J1 | meta 设备实例化 qwen3_5 结构 | `AutoModelForCausalLM.from_config` 成功，参数量 ≈27B |
| J2 | 线性注意力前向可走通 | 极小随机输入 forward 不报 `linear_attention` 错 |
| J3 | 至少一条 LoRA 路径可用 | Unsloth / LLaMA-Factory / 原生 transformers+peft 三者有一 |

J1–J3 全绿 → 放心按手册停服训 G3；任一不过 → 先解决适配，**绝不硬停服**。

**另外建议顺手做的一件事**：G1/G2 完全不需要停服（结构头只有 22.9 万参数，CPU 都能训）。可以先把 G1 的合成数据生成器 + G2 的结构头 torch 版做出来，**在 vLLM 照常服务的同时**就把数理层跑通——等 G0.5 结论明确后，再一次性停服做 G3/G4。这样最省时间。
