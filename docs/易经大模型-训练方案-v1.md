# 易经大模型 · 训练方案 v1

> 目标：在 DGX Spark（GB10 / 121 GiB 统一内存）上，以《周易》方圆图与六维卦象结构为核心，把 27B 基座训成"以易为骨、以儒道为魂"的圣人之思模型。
> 本文回答四个问题：**拿什么训、怎么灌进去、怎么判断成了、先做哪一步。**

---

## 零 · 先厘清根本认知：什么能"训"进权重

大模型只学**token 序列的条件概率**。任何"知识"要进权重，必须先变成文本序列。
所以用户最初的设想"拿方圆图直接训练"，必须经过一次转译。

| 想训的东西 | 能直接训吗 | 正确做法 |
|---|---|---|
| 周易全文（卦辞·爻辞·彖·象·文言·系辞·说卦·序卦·杂卦） | ✅ 能 | 分卦分爻切块，配释义 |
| 方圆图的图像 | ❌ 图形不是 token | 转成「坐标↔卦名↔关系」三元组 |
| 六维超立方体的几何 | ❌ 几何不是 token | 转成「汉明距离/邻接/最短路」判定 |
| 错卦·综卦·互卦·变卦 | ✅ 能 | 程序穷举成问答对 |
| 起卦→推演→断事的思维过程 | ✅ 能，且**最有价值** | 写成完整思维链 |
| 奇门遁甲 / 紫微斗数 | ⚠️ 规则尚未实现 | 需先建独立规则引擎，本期不做 |

**一句话**：不是把图塞进模型，而是**把图定义的关系，变成模型能判定的问答**。

好比没人能让模型"看见"立方体，但可以让它精确回答"从 000000 到 111111 最少走几步、有几条最短路、哪些点只差一位"。当它能稳定答对这些，它就在内部建立了这个立方体的表征。

**而我们的最大优势是**：这些答案由 Python 程序算出，不靠人写，所以**零错误、可无限批量生成**。这是小团队能训出高质量模型的唯一现实路径。

## 一 · 卦的"数字代码"体系（用户问的核心）

同一卦有 **5 套索引**，必须在训练数据里反复出现，让模型建立"其实是一个东西"的映射。

| 索引类型 | 取值 | 示例（乾卦） | 示例（坤卦） |
|---|---|---|---|
| 六爻二进制（自下而上，阳1阴0） | `000000`–`111111` | `111111` | `000000` |
| 通行本序数 | 1–64 | 1 | 2 |
| 先天八卦数（上卦/下卦） | 乾1 兑2 离3 震4 巽5 坎6 艮7 坤8 | 上1下1 | 上8下8 |
| 方图坐标 | 行 0–7 / 列 0–7 | (0,0) | (7,7) |
| 圆图时序位 | 0–63（邵雍标准圆图序） | 0 | 32 |

**超立方体的数学骨架**（已用 `verify_shuxue.py` 12/12 验证）：

- 64 卦 = 立方体 `{0,1}^6` 的 64 个顶点，每爻 1 bit
- 卦 A 与卦 B 的点积 = `6 − 2 × 汉明距离`
- 邻居分布（按距离 k）：`1, 6, 15, 20, 15, 6, 1`（即 C(6,k)）
- 对径点（距离 6）= **错卦**（阴阳全反）
- 镜像 = **综卦**（上下颠倒）
- 变化一爻 = 沿一条边走到相邻顶点 = **动爻**

这套东西就是"球"的可计算表述。**它不需要图像，它需要的是能算的规则。**

## 二 · 四条训练轴

### 轴 1 · 数理（形）—— 卦的骨架，1.5 万条

**为什么先做**：答案确定、可程序穷举、loss 下降最快，是地基。

| 题型 | 生成方式 | 预估条数 |
|---|---|---|
| 卦名 ↔ 六爻二进制互查 | 穷举 64 × 2 | 128 |
| 卦名 ↔ 上下卦 / 卦德 / 五行 / 方位 | 查 `xiangshu.py` 表 | 320 |
| 错卦 / 综卦 / 互卦三元查询 | 穷举 64 × 3 | 192 |
| 任意两卦汉明距离与关系判定 | 全对 64×63/2 = 2016，全量 | 2,016 |
| 邻居枚举（某卦差一爻的所有兄弟卦） | 64 × 6 | 384 |
| 方图坐标 ↔ 卦名（含行列语义） | 64 × 2 | 128 |
| 圆图时序位 ↔ 卦名（含节气） | 64 × 2 | 128 |
| 二十四节气 ↔ 辟卦 ↔ 律吕 ↔ 黄道十二次 | 24 × 4 | 96 |
| 六十甲子纳甲 / 爻辰 | 60 × 6 | 360 |
| 384 爻题（初九、六二…）↔ 爻位 ↔ 阴阳 | 384 × 2 | 768 |
| 十二消息卦 → 其余 52 卦的归属推演 | 64 | 64 |
| 起卦（梅花易数）年月日时 → 本卦/动爻/变卦 | 随机 3000 组 | 3,000 |
| 变卦推演链（含三变、五变、六变） | 64 × 若干 | ~2,000 |
| 卦序逻辑（序卦传相邻关系为何如此） | 63 对 | 63 |

**样例格式**（SFT，messages 三段式）：

```json
{"messages":[
 {"role":"system","content":"你是精通《周易》象数的助手。数理问题必须精确，不确定时明确说明。"},
 {"role":"user","content":"泰卦（䷊）与否卦（䷋）的汉明距离是多少？它们是什么关系？"},
 {"role":"assistant","content":"泰卦六爻自下而上为 111000，否卦为 000111。\n逐位比较：六位全不相同，汉明距离 = 6。\n在六维超立方体上二者是对径点（距离最大），即互为错卦。\n错卦之义：泰为通、否为塞，一体之两面——泰极则否，否极则泰。"}
]}
```

**可验证性**：100% 自动判分。

### 轴 2 · 语义（辞）—— 说得准，5 千条

**数据源**：`jingwen.py`（64 彖传 + 386 爻辞 + 384 小象，已与 `bollwarm/ZHOUYI` 交叉校验，我方 0 错）+ `jingyi.py`（50 概念 / 55 关系，每条带经典依据）。

| 题型 | 说明 | 预估 |
|---|---|---|
| 卦辞 / 彖传 / 爻辞 / 小象 原文默写 | 严格逐字 | 64+64+386+384 → 取 900 |
| 逐句白话疏解 | 一对一释义 | 900 |
| 概念贯通（元亨利贞在乾/坤/屯/随…的差异） | 50 概念 × 多卦 | 800 |
| 义理关系（55 条，每条展开成问答） | 含出处 | 550 |
| 跨卦比较（屯蒙相综、需讼相综…） | 32 对相综 | 480 |
| 卦名训诂（字源 → 卦义） | 64 | 64 |
| **反幻觉样本（负例）** | 故意问不存在的爻辞，答"此爻不存在" | 300 |

**关键**：**反幻觉样本必须占一定比例**。模型编造爻辞是这个项目最大的风险。

### 轴 3 · 象意（象）—— 想得到，3 千条

**这一轴最玄，必须锚定经典**，不能自由发挥，否则训出来就是玄学糊弄。

依据：《说卦传》卦象、《杂卦传》、王弼《周易注》、程颐《伊川易传》、朱熹《周易本义》。

| 题型 | 说明 | 预估 |
|---|---|---|
| 卦象 → 自然物象（乾为天/为马/为首…） | 说卦传穷举 | 400 |
| 物象 → 人事情境（如"坎为水为险"→ 处险之道） | 逐项展开 | 800 |
| 情境 → 取象（给一个人事场景，选最贴合的卦象并说明依据） | 半自动构造 | 1,000 |
| 爻位象（初爻为始、上爻为终、二五得中…） | 规则化 | 300 |
| 卦象互涉（互卦揭示内在、变卦指示去向） | 500 |

**红线**：每条象意必须给出经典出处，无出处的不生成。

### 轴 4 · 逻辑（推）—— 推得通，2 千条 ★最有价值

这是"圣人思维"真正的载体，也是与普通"会背易经的模型"的分水岭。

**格式**：完整四步思维链，对齐 `sage.py` 的 SAGE_SYS。

```
【立心】此问在明何事，当以何心应之
【格物】起卦 → 定卦 → 卦象分析（卦德/五行/方位）→ 互卦察内 → 变卦观变
        → 时空坐标（节气/律吕/黄道次）→ 义理溯源
【致知】综合判断，得贯通之见（不是罗列，是收敛）
【笃行】落到可执行的具体建议，含时机与分寸
```

| 题型 | 说明 | 预估 |
|---|---|---|
| 单卦断事（问事 → 定卦 → 断） | 64 卦 × 多场景 | 800 |
| 起卦全过程（报数 → 本卦 → 动爻 → 变卦 → 断） | 梅花易数 | 600 |
| 卦际推演（本卦→互→变→错综，一条链讲透） | 多层推演 | 400 |
| 圣人之思（抽象问题用易理贯通，如"如何处理困境"） | 跨卦综合 | 200 |

**质量 > 数量**。这一轴不能用模板批量灌，必须逐条打磨，否则模型学到的是"套话格式"而非推理。

## 三 · 能力边界：会什么、不会什么

**必须一次讲清楚，否则训练完会失望。**

| 体系 | 本期能否训 | 原因 |
|---|---|---|
| 周易本经 + 义理 | ✅ 能 | 语料充足，规则清晰 |
| 象数结构（方圆图/超立方体/错综互变） | ✅ 能 | 已全部程序化，可穷举 |
| 梅花易数起卦 | ✅ 能 | `qigua.py` 已实现 |
| 六爻纳甲（世应/六亲/六神/用神） | ⚠️ 需先补引擎 | 规则未实现，约 1 周工作量 |
| 奇门遁甲（九宫/八门/九星/八神/三奇六仪） | ⚠️ 需独立工程 | 完全不同的体系，独立语料 + 独立引擎 |
| 紫微斗数（十二宫/十四主星/四化） | ⚠️ 需独立工程 | 同上 |

**结论**：**一次训练不可能全会。** 强行混训的结果是三样都不精。
必须**分期**：本期只做「周易 + 象数 + 梅花易数」，把这一套做到"引经据典、数理无误"，比"什么都懂一点、什么都不可靠"有价值得多。

## 四 · 训练路线（分四阶段）

| 阶段 | 内容 | 数据量 | 耗时 | 判据 |
|---|---|---|---|---|
| **S0 冒烟** | 现有 504 条跑通链路 | 504 | ~15 min | loss 正常下降，无 NaN |
| **S1 数理** | 只训轴 1 | 1.5 万 | ~2-3 h | 数理评测 >95% |
| **S2 语义+象意** | 加轴 2、3 | +8 千 | ~2 h | 原文默写 >90%，幻觉率 <5% |
| **S3 逻辑** | 加轴 4（curriculum 最后上） | +2 千 | ~1 h | 人工评分通过 |

**Curriculum 顺序很重要**：先骨架（数理）→ 再血肉（语义）→ 再神采（象意）→ 最后思辨（逻辑）。
如果一开始就把最难的逻辑混进去，模型会在简单题上欠拟合、难题上过拟合。

**技术参数**（已实测确定）：
- 基座：`Qwen/Qwen3.8-27B` BF16，26.896 B 参数，50.1 GiB
- 微调：**LoRA r=16, alpha=32**，400 个模块全挂，可训 108.79 M（0.403%）
- 不挂：`in_proj_a`/`in_proj_b`（GatedDeltaNet 标量门控，无意义）、`lm_head`、`embed_*`
- 不用 QLoRA/4bit：BF16 LoRA 峰值约 61 GiB，121 GiB 放得下，**规避 bitsandbytes 在 Blackwell(sm_120) 的兼容风险**
- 全参数微调：需 304 GiB，**物理不可行**，不要尝试

## 五 · 判断标准（怎么知道训成了）

分四层评测，**每层独立打分**，不看单一 loss。

### L1 数理硬指标（自动判分，0/1）
从轴 1 抽 500 条做留出集，逐条比对：

| 指标 | 目标 |
|---|---|
| 卦名↔二进制互查 | >98% |
| 错/综/互卦查询 | >95% |
| 汉明距离判定 | >95% |
| 节气↔辟卦↔律吕 | >90% |
| 爻题↔爻位 | >95% |

> 这些是确定性知识，**达不到 95% 就是没学会，不用找借口**。

### L2 语义准确率
- **原文默写**：对照 `jingwen.py` 逐字比对，目标 >90%
- **义理阐释**：关键概念覆盖率 + 是否引据经典，人工抽检 100 条

### L3 逻辑自洽与幻觉率 ★红线
- **幻觉率**：专门构造 100 个"陷阱问题"（不存在的爻辞、张冠李戴的卦象、错误的错卦配对），看模型是否敢于说"没有""不对"。
  **目标：<5%**。这一项超标，整个模型不可用。
- **推理自洽**：给 50 个真实情境，检查推演链是否前后矛盾、是否引用了自己刚否定的东西。

### L4 象意合理性（人工）
抽 100 条，评"是否有经典依据、是否牵强"。这一层无法自动判分，必须人看。

### 综合判定
```
可用 = L1 全部达标  AND  L2 原文 >90%  AND  L3 幻觉率 <5%
优秀 = 上述 + L4 人工评分 >80分  AND  能对一个开放问题给出"收敛而非罗列"的答案
```

**最有说服力的验收方式**：拿 20 个你自己真实遇到的问题（油气项目的、中医辨证的、人事决策的），让基座模型和微调模型各答一遍，盲评。能看出差别，就是真的训进去了。
