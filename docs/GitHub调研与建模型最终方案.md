## 二、差异化判断：别人做到哪、我们做什么

**别人全做的是**：占卜起卦、检索古籍、中医问答、卦象可视化。没有一个把"六十四卦"本身做成**可训练的模型结构**，更没有人把"圣人思维"做成推理引擎。

**我们的空白点（也是你的核心诉求）**：

1. **六十四卦 = 六维布尔超立方体的 64 个顶点** → 做成**卦象专家路由层（超立方体 MoE）**，64 卦 = 64 个可训练专家，"定卦"= 触发机制（路由）
2. **圣人思维引擎**：把"立心→格物→致知→笃行"做成 R1 推理链，用经义贯通油气/中医/工作

这两样 GitHub 上**没人做**，是真正属于你的创新。

## 三、最终技术路线（两条腿 + Qwen3-14B）

```
[数据地基]  bollwarm/ZHOUYI 校验经文 + ichingshifa 起卦算法
     │
     ├─ 腿 A：卦象专家路由层（超立方体 MoE，64 卦=64 专家）
     │        · 用已建的象数(错综互/方圆/节气)做结构先验注入
     │        · 定卦=路由，只激活 top-k 卦
     │
     └─ 腿 B：Qwen3-14B LoRA 微调（照搬 qwen-tcm-finetune 模板）
              · 数据 = 经文/义理/方圆图/节气 生成 R1 推理格式问答对
              · 让模型"内化经义"，而非"检索古籍"

融合：卦象层做 Qwen 的"思维前缀/路由"，RAG 古籍检索做兜底
```

## 风险提示

1. **GB10（128GB 统一内存）跑 14B 全参微调会吃力**，用 QLoRA 4bit + LoRA 可稳跑；8B 更快，可先拿 8B 验证流程再切 14B。
2. **卦象 MoE 是创新架构，无现成轮子**，需自己写 + 小规模 POC 验证，别一上来就上大模型。
3. **训练数据质量 > 数量**：先用结构化经文（几百~几千条高质量问答对）验证，再扩到古籍注释语料。
